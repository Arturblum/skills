Before: a Task with a WhatsApp approval form

Approval is a form on a Task. The send happens on the side, and the run never finds out what became of the message.

On a narrow screen the diagram scrolls sideways inside its frame.

    After: the Notify node

    Approval is Notify's own step. The run sends the message itself and waits for Notifications to report whether it was delivered.

      Assumptions to confirm

      • The message text is filled from the incident when it is proposed, because Notifications checks the sent text against the approved text. ADR 0062 says "when sent", so this needs a note or a new ADR.
      • sendMessage deduplicates on the body id today, while ADR 0095 puts the Idempotency Key in a header. I would make the two the same value.
      • A role maps to its team's field-app group through configuration until #378 builds real roles.
      • The Dispatcher approval step is frontend work the ticket does not name.
      • A failed send is recorded and the path continues (the ticket's acceptance criterion), which differs from #453's default of ending the run.
